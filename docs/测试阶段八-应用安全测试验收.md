## 安全边界

只访问本机显式 `127.0.0.1` 地址，目标白名单拒绝域名、路径和用户信息混入。使用临时目录、合成旅行与订单、Mock 模型/OCR/图存储；不调用真实模型，不扫描第三方域名。下载工具、漏洞库、依赖与镜像属于获取测试依赖，不是对其服务执行扫描或攻击。

ZAP 使用官方校验和验证的 2.16.1 发行包。只加载所需插件、关闭更新和遥测，只启用 `40012` 反射 XSS 与 `40018` SQL 注入规则，强度 LOW、每目标 1 线程、两条固定 GET 地址、不递归、不启用命令、文件写入、时间延迟或外部回连规则。最终观测站点全部是两个本地端口。

工具版本及范围固定在执行记录中。ZAP 2.16.1 为旧版本，插件规则覆盖不是最新；应在后续补验时升级并复核同等安全策略。

## 环境失败与清理

1. 首轮嵌入式 PostgreSQL 在 macOS 启动时报
   `postmaster became multithreaded during startup`，失败批次保留。认证修复批次
   已成功启动本机数据库与 Spring 服务并完成 58 项 HTTP 探针；这仍不是最终容器环境。
2. Docker daemon 不可用。隔离 Colima 的 VZ 启动失败，日志指出当前进程缺少 virtualization entitlement；没有修改系统权限或用户默认虚拟机。镜像下载与 Java 原始 rootfs 扫描没有完整结果，不能把退出状态误当漏洞发现。
3. 初次 Trivy JAR/fs 扫描识别包数为零，作无效覆盖处理；后续生成 SBOM 并扫描成功。它仍不是最终容器操作系统扫描。
4. ZAP 初版执行器参数重名导致主动扫描前失败，已修复并实际复测；配置证据改为读取执行后的 LOW/enabled 状态。早期失败记录保留。
5. 最后 Gitleaks 发现 42 个原始命中：41 个来自本轮失败虚拟机的磁盘/临时 SSH 材料，1 个明确无效测试 Token。未读取或输出密钥明文，未向第三方验证凭据；销毁 `colima-stage8` 及附加盘、删除其临时 SSH 凭据，并将无效测试值缩短后复扫零命中。**没有增加目录豁免来绕过告警。**
6. Java、嵌入式 PG、FastAPI、ZAP、Vite、浏览器测试进程均退出。失败 ZAP home、复制的临时工具目录和虚拟机缓存已清理。保留校验过的 ZAP 发行包和扫描缓存便于复测，不含应用秘密。
7. 最终证据目录另行扫描，原始 6 个命中均为失败测试回显的固定 `test-service-token`。仅对报告日志/XML中的这个精确合成值进行处置后复扫零命中；原始报告保留，前端构建扫描不采用这项豁免。此扫描不解包浏览器 trace 压缩包。

当前工作区没有 `.git`，不能运行历史扫描、比较提交引入范围或声称已提交修复。Gitleaks 当前源码配置排除依赖、构建目录和报告，因此前端产物另行扫描；Git 历史仍为强制门禁缺口。
