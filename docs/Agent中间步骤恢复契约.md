# Agent 中间步骤恢复契约

## 范围

仅支持规划任务在 `AGENTS_RUNNING`、进度 40、计划仍为 `GENERATING`、
没有已发布计划结果时恢复。输入必须与首次快照的用户、需求、订单、计划版本、
编排配置一致。其他步骤保留显式失败或已有完成结果对账行为。

不保证外部非幂等副作用恰好执行一次。当前专家 Agent 只产生候选或读取数据；
进程死亡前未提交的步骤可重新调用。已提交且校验成功的步骤不得重新执行。
FAILED/TIMEOUT 结果不复用，DEGRADED 结果保留降级信息，不能提升为成功。

## 数据与隔离

- `planning_checkpoint`：task 主键、输入 SHA-256、租户指纹、最小化 Coordinator
  输入、检索结果、执行令牌、到期时间。只存后端数据库，不通过 API 暴露。
- `agent_step_checkpoint`：`(task_id, agent_name)` 唯一、Prompt 版本、最小化输入
  SHA-256、租户 SHA-256、执行令牌、Agent 执行行引用及完整结果。
- Coordinator 输入增加可选 `executionToken` UUID，仅内部调度设置；旧调用
  省略时保持原行为。字段不发送给专家 Agent。专家使用 task/agent 派生的稳定
  逻辑 ID，避免重建上下文后指纹漂移。
- 结果写入与 `agent_result` 完成在同一 PostgreSQL 事务提交。检查点结果重新
  经过 Agent 输出 Schema、状态、名称校验。禁止从日志、展示摘要恢复。
- 令牌变化后，旧工作线程不能写入或读取当前步骤结果。同一令牌重复启动
  正在运行的步骤被拒绝。终态、取消、过期检查点禁止继续调用。
- 数据保留时间配置化，过期检查点清理；不会延长原始保留期限。

## 恢复流程

1. 使用 PostgreSQL 会话 advisory lock 独占任务，锁随连接/进程断开释放。
2. 核对任务最新终态、取消、恢复预算和计划阶段，取得新的执行令牌。
3. 保留进度 40，复用首次最小化输入及检索结果，不重新检索或回退进度。
4. 已完成步骤返回原校验结果及证据；未完成步骤新建执行行并标记旧行中断。
5. 保持串行依赖与并行候选分支。Coordinator 输出后按既有规则生成候选。
6. 任务完成后清理私有检查点，展示用 Agent 执行历史仍保留。

恢复仅由真实数据库快照触发，禁止测试手工伪造成功结果。恢复与正常执行共享
锁保护；活跃执行不能被定时恢复器抢走。独占连接损坏时执行中止，不能继续发布计划。

## 验证

- Research 执行中强制终止进程，Requirement 结果已提交。
- 并行 Accommodation 执行中终止，Transport/Recommendation 已提交。
- 重启后同一 task 完成，两方案可读，已提交步骤和模型调用次数不增加。
- 验证终态、取消、指纹/租户/Prompt 变化、旧令牌、并发竞争、过期与损坏数据。
- 进度不回退，原 traceId 保留，PARTIAL_SUCCESS 不伪装 SUCCEEDED。
