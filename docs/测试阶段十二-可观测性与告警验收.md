## Trace 验证

12 个组件的静态证据均通过。前端仅接收响应头中的 Trace 信息，不向普通页面暴露
内部 Span 细节；Spring Boot、FastAPI、MCP、A2A、RAG 和模型调用具备 Span 或
领域化投影证据。Kafka Producer 写入 `traceparent`，Consumer 通过事件因果上下文
继续关联。

`taskId` 不能直接替代 `traceId`，但当前持久化实体和控制器支持从任务记录查询
`traceId`，再进入受控开发者 Trace 查询入口定位完整链路。

仍有 3 个开发者投影缺口：

| 缺口 | 状态 | 说明 |
| --- | --- | --- |
| Neo4j | `RAW_SPAN_ONLY` | 原始 Jaeger Span 存在，但 DeveloperTraceService 尚无专用分类 |
| LanceDB | `RAW_SPAN_ONLY` | 原始 Jaeger Span 存在，但 DeveloperTraceService 尚无专用分类 |
| RuleEngine | `RAW_SPAN_ONLY` | 原始 Jaeger Span 存在，但 DeveloperTraceService 尚无专用分类 |

## 隐私与脱敏

本轮扫描阶段十二配置、Prometheus 规则和 runner，未发现 API Key、Bearer Token、
手机号、证件号或完整订单号等禁用模式。开发者 Trace 和日志链路均要求走
`SensitiveDataSanitizer`，普通用户界面不得展示内部错误、协议状态码、凭据或原始
隐私内容。

真实小流量验证导出的指标、日志、Trace、截图和告警通知仍必须单独执行脱敏扫描；
不得把本轮离线扫描扩大解释为真实环境隐私验收。
