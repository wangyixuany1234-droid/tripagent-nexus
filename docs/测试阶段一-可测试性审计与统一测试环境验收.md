## 8. 失败案例与修复

1. 首次非容器集成入口仍加载两个 Testcontainers 类，Docker 不可用导致错误。
   已在 Surefire 命令中显式排除容器类，复跑 28 项通过。
2. 文档重试测试只等待文档状态，没有等待任务投影，出现
   `RUNNING` 与 `WAITING_CONFIRMATION` 的竞态。已使用 Awaitility 等待任务终态，
   定向回归 3 项及完整集成层均通过。
3. Maven JUnit XML 原先仍写入模块 `target`。已在 POM 显式绑定
   Surefire/Failsafe 报告目录，单元、集成和契约 XML 均已写入统一目录。
4. 安全扫描原始 JSON 与运行摘要曾同名。已拆分为 `*-findings.json` 和执行摘要，
   复跑后原始结果与状态均可由 CI 独立读取。
5. Colima 启动后 Docker CLI 可用，但 Testcontainers 不读取 Docker CLI context，
   默认查找 `/var/run/docker.sock`。新增 context 解析脚本，将当前 Unix socket
   显式传给 Testcontainers，并保留调用方已设置的 `DOCKER_HOST`。
6. Toxiproxy 的 Docker Hub 标签不存在，改用
   `ghcr.io/shopify/toxiproxy:2.12.0`；同时修正健康检查端口和初始化幂等性。
7. QA Compose 首次实启发现 Jaeger 存储权限、API 上传目录、MCP 契约构建输入和
   Web 构建上下文/IPv6 健康检查问题，均已修复并通过全服务健康检查。
8. 完整补跑期间 WireMock 正常场景在 `250 ms` 客户端截止时间下出现一次调度
   抖动。客户端改为复用实例并使用 `2 s` 截止时间，仍小于故障 Stub 的
   `3 s` 延迟；定向回归 3 项和完整集成 28 项均通过。

首次失败证据保留在：

- `output/test-results/20260908T-stage1/json/java-integration-initial-failure.json`
- `output/test-results/20260908T-stage1/logs/java-integration-initial-failure.log`
