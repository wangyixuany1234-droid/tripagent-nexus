# 阶段五：双层 RAG 与 GraphRAG

## 完成项

- 定义公共知识写入、用户记忆写入、混合检索和图检索私有 API。
- LanceDB 使用 `travel_public` 与 `user_memory` 两张物理表。
- 用户记忆在召回前按 `tenantId + userId` 过滤，包装证据前再次校验。
- 写入账本保存请求摘要和响应，支持幂等重放及冲突拒绝。
- 查询链路包括改写、意图路由、地点/日期过滤、向量与中文 n-gram
  关键词召回、融合、图扩展、Cross-Encoder 重排、去重和压缩。
- Neo4j 支持地点、区域、交通和营业关系的有界遍历。
- 证据只能来自已存储 LanceDB 行或 Neo4j 节点，模型不能伪造来源 ID。
- 无证据和实时查询分别标记 `evidenceInsufficient` 与
  `realtimeToolRequired`。

## 限制

- 实时排队、天气等数据由 MCP 供应商工具提供，RAG 不伪造实时证据。
- LanceDB 和 Neo4j 是可重建索引，源删除传播与周期重建属于运维流程。
- Mock 模式只验证链路和确定性结果，不代表 DeepSeek 或真实图服务质量。

## 验收

双层隔离、混合召回、GraphRAG、日期过滤、重排和证据可追溯性均有 pytest
覆盖；真实 Neo4j 连通性由阶段十 Testcontainers 验证。
