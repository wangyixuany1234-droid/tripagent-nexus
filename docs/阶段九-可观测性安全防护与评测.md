# 阶段九：可观测性、Guardrails 与评测回放

## 完成项

- OpenTelemetry 覆盖 HTTP、Kafka、模型、RAG、重排、Agent 委派、MCP、
  A2A、数据库和规则校验。
- Span 记录延迟、状态、错误类型、模型、Prompt 版本、Token、结果数、
  Agent 和工具名。
- Trace 与日志排除密钥、Authorization、证件号、完整订单号、原始图片、
  OCR 原文、Prompt/模型输出和未脱敏偏好。
- Guardrails 包括 Prompt Injection、上传安全、HTTPS/域名白名单、模型
  Schema、不可信检索隔离、PII 和预算/支付边界。
- `ORDER_CREATE`、`PAYMENT`、`CANCELLATION`、`REAL_COST` 使用持久化 HITL。
- 确认校验 Actor、动作 ID、版本、风险、金额、币种和过期时间。
- 过期状态和审计通过独立事务持久化，执行前再次检查过期和精确授权。
- `phase-9-v1` 数据集包含 12 个必需场景并复用异步任务、轮询和 SSE。

## HITL 示例

创建候选动作不会执行支付：

```bash
curl -X POST http://localhost:8080/api/v1/actions \
  -H 'Content-Type: application/json' \
  -H 'X-Actor-Id: user-42' \
  -H 'Idempotency-Key: payment-proposal-0001' \
  -d '{
    "type":"PAYMENT",
    "resourceId":"<resource-id>",
    "riskDescription":"将收取 CNY 1280.0000",
    "amount":1280.0000,
    "currency":"CNY",
    "expiresAt":"<future-utc-instant>"
  }'
```

确认动作仍不会直接调用供应商：

```bash
curl -X POST http://localhost:8080/api/v1/actions/<action-id>/confirm \
  -H 'Content-Type: application/json' \
  -H 'X-Actor-Id: user-42' \
  -H 'Idempotency-Key: payment-confirm-0001' \
  -d '{
    "actionId":"<action-id>",
    "expectedVersion":0,
    "acknowledgedRisk":true,
    "acknowledgedAmount":1280.0000,
    "currency":"CNY"
  }'
```
