# 阶段十一：前端工程与视觉系统

## 1. 本阶段范围

本阶段在阶段十冻结契约基础上搭建可运行的 React 前端、统一 API 层和视觉
系统，只实现 App Shell、基础状态组件、旅行领域展示组件与独立预览页。
旅行创建、订单上传、方案详情、重规划、HITL 和评测管理等完整业务页面不在
本阶段实现。

## 2. 完成项

### 2.1 前端工程

- 使用 React、TypeScript、Vite 和 Tailwind CSS v4 建立前端工程。
- 使用 shadcn/ui 约定、Radix primitives、Lucide 图标和 `components.json`。
- 接入 TanStack Query、Zustand、React Router、React Hook Form、Zod、
  ECharts、MapLibre GL、Vitest、React Testing Library 和 Playwright。
- `VITE_API_BASE_URL` 是唯一公共 API Base URL 配置。
- 前端没有 `DEEPSEEK_API_KEY`，不直接请求模型、地图供应商、天气、检索或
  FastAPI。
- ECharts 和 MapLibre 使用动态拆包，组件预览页按路由懒加载。

### 2.2 契约与 API

- 在开发契约和冻结契约中新增向后兼容的 `GET /api/v1/health`。
- health 返回 `status`、`service`、`apiVersion`、`providerMode` 和
  `timestamp`，其中 `providerMode` 明确区分 `LIVE` 与 `MOCK`。
- Spring Boot 实现 health 接口，且 MCP 服务关闭时不会破坏应用上下文。
- 重新生成 TypeScript Fetch SDK，新增 `SystemApi` 和 `SystemHealth`。
- 新增 `GET /api/v1/maps/tiles/{zoom}/{x}/{y}.png`，由 Spring Boot 在外部
  域名白名单内代理真实世界地图瓦片；浏览器通过 generated `MapsApi`
  获取，不直接连接地图供应商。
- 前端只通过 generated SDK 和 `apiAdapter` 调用后端。
- 统一 Fetch 层注入 `X-Request-Id`、携带 Cookie、读取 `X-Trace-Id`，并
  处理 401、403、409、422、429 和 5xx。
- 401 会发布会话失效事件；错误进入全局通知中心，服务端 `traceId` 仅保留
  在内部状态中，不在普通用户界面显示。
- 长任务先通过 generated `TasksApi` 建立 SSE 请求，断流后自动降级为
  轮询；支持 `Last-Event-ID` 和终态停止。

### 2.3 App Shell

- 桌面固定侧边导航，手机使用可访问的抽屉导航。
- 顶部导航包含规划状态、演示数据提示、全局通知和用户菜单，不展示连接
  状态或运行模式等技术信息。
- 实现面包屑、页面标题区、跳过导航链接和 404 页面。
- 亮色、深色和跟随系统三种主题可切换并持久化。
- 主导航、菜单、通知和主题切换支持键盘操作。

### 2.4 视觉组件

- `Skeleton`
- `EmptyState`
- `ErrorState`
- `Stepper`
- `StatusBadge`
- `BudgetCard`
- `EvidenceBadge`
- `ConflictBadge`
- `AgentProgress`
- `MapContainer`
- `Timeline`

预算、证据、冲突、Agent、地点和时间线组件直接使用 generated SDK 模型，
没有手写重复领域类型。MapLibre 使用后端代理的 OpenStreetMap 世界地图，
支持全球平移和缩放；地点、名称标签和路线均按真实经纬度锚定，并展示地图
版权归属。

### 2.5 组件预览

- `/` 是不伪造业务数据的空工作区，可真实读取后端 health。
- `/design-system` 是独立组件预览页，覆盖主要状态、图表、地图和时间线。
- 预览样例集中在 `pages/preview-data.ts`，只用于视觉验收，不作为真实接口
  成功结果。
- Error State 默认不显示，只有用户切换到“错误状态”时才展示，并明确标注为
  无副作用的组件示例，不触发请求、刷新或页面跳转。

```bash

  npm --prefix apps/web run dev -- --host 127.0.0.1
```

## 7. 遗留问题

- 旅行、订单、方案、HITL 和评测的完整业务页面留到后续阶段。
- 上游用户登录与真实网关 Token 注入尚未接入；当前 API 层已保留安全的
  内存 Token Provider，不持久化凭据。
- 默认瓦片源为 OpenStreetMap，生产部署需按流量规模配置合规的专用或
  自托管瓦片服务，并同步调整 `MAP_TILE_BASE_URL`、`MAP_TILE_USER_AGENT`
  与 `ALLOWED_EXTERNAL_HOSTS`。
- MapLibre 与 ECharts 属于重型依赖，当前已拆为独立异步 Chunk，构建仍会
  给出单 Chunk 大于 500 KiB 的性能提示。
- 当前环境没有 `gitleaks` 可执行文件，本阶段通过受限源码检索确认前端
  没有 API Key、Authorization 样本或 `DEEPSEEK_API_KEY`。
