## 5. 主流程 E2E

`EndToEndPlanningIntegrationTest` 验证：

1. 创建旅行并保存北京三日游需求。
2. 上传脱敏航班图片。
3. 解析任务进入 `WAITING_CONFIRMATION`。
4. 人工修正 `startTime` 和 `endTime`。
5. 解析任务进入 `SUCCEEDED`。
6. 发起方案生成。
7. 读取 SSE 完成事件，并与轮询终态、任务 ID 和进度核对。
8. 获取 `BALANCED`、`LOW_TRANSIT` 两个方案。
9. 查看 `COMMUTE_TIME_INSUFFICIENT` 冲突和自动修复状态。
10. 锁定航班、删除餐饮、调整预算和节奏后重规划。
11. 确认新版本方案。
12. 提交 5 分反馈。

定向测试结果：7 个测试通过，0 失败，0 错误，其中包括 6 个契约测试和
1 个完整业务 E2E。

## 8. Mock 与真实模式

| 能力     | Mock 模式                    | 真实模式                          |
| -------- | ---------------------------- | --------------------------------- |
| 模型     | 固定结构化输出，Token 可为 0 | DeepSeek 实际延迟、Token 和错误   |
| OCR      | 脱敏夹具和固定抽取           | Tesseract/Poppler 加 DeepSeek 视觉模型 |
| RAG/重排 | 确定性向量、查询分析和重排   | DeepSeek Embedding/重排           |
| MCP      | 明确 `providerMode=MOCK`     | 调用配置的真实供应商              |
| 规划     | 可复现候选和证据             | 实际模型与工具输出                |

Mock 只证明流程、契约和确定性规则，不证明第三方质量或可用性。

- 未在源码、配置、测试快照或 SDK 中写入真实 API Key。

- SSE 使用 PostgreSQL 事件序列，轮询读取同一任务事实源。
