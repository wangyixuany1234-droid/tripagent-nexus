# 阶段十四：辅助页面、全量联调与发布验收

## 1. 本阶段范围

本阶段补齐行程工作台、用户偏好与记忆、反馈中心、受控开发者追踪和系统
状态五个辅助页面，并完成北京三日游浏览器主流程、异常场景矩阵和发布前
检查。

所有新增前端请求均通过冻结 OpenAPI 生成的 TypeScript Fetch SDK 和统一
API Adapter。浏览器不直接调用模型、检索、地图供应商或内部服务，也不
持有服务端密钥。

## 2. 完成项

### 2.1 行程工作台

- 按进行中、待确认、已完成和失败任务分组查看。
- 支持按目的地、出发日期、返程日期和任务状态组合筛选。
- 进度、状态和结果入口均来自后端任务投影，不使用前端计时器推算。
- 未完成任务可继续进入资料复核或规划进度页，已生成方案可进入结果页。
- 非终态任务支持幂等取消，取消期间、成功和失败均有明确界面状态。
- 普通用户界面不展示任务内部标识。

### 2.2 用户偏好与记忆

- 展示用户主动设置和根据反馈推断的偏好，并以用户语言区分来源。
- 支持新增、修改、删除主动偏好。
- 修改推断偏好后由后端转为用户主动设置。
- 推断偏好可拒绝，已拒绝记录保留为可审计状态。
- 拒绝或删除偏好前，后端按 `tenantId`、`userId` 和 `preferenceId`
  清理 LanceDB 用户记忆；清理失败时不删除关系数据，避免两个存储状态
  不一致。
- 所有输入继续经过参数约束和 Prompt Injection Guard。

### 2.3 反馈中心

- 支持对方案、地点、预算结果和推荐依据提交喜欢或不喜欢。
- 支持原因标签、评分和补充说明。
- 反馈目标与旅行、方案归属关系由后端校验。
- 只有方案或地点反馈同时包含态度和原因标签时，才可形成模型推断偏好。
- 预算和推荐依据反馈仅用于改进内容，不直接写入用户记忆。
- 形成的推断偏好仍可由用户修改、拒绝或删除。

### 2.4 开发者追踪

- 页面入口只在后端声明开发工具可用时出现，接口同时允许可信管理员角色。
- 只接受 32 位小写十六进制追踪编号。
- 按模型、知识检索、Agent、MCP、A2A 和 Kafka 分类展示链路。
- 后端限制属性数量和长度，并对 Prompt、Authorization、API Key、用户字段
  及常见敏感数据脱敏。
- 前端在渲染前再次过滤敏感属性。
- 普通业务页面继续隐藏追踪编号和内部诊断信息。

### 2.5 系统状态

- 展示数据存储、会话与任务状态、异步任务处理和旅行知识检索的可用性。
- 展示智能规划、地图、天气和资料检索能力。
- 演示运行模式统一显示“当前展示演示数据”，真实运行显示“真实服务”。
- Provider 转换为用户可理解的名称。
- 响应不包含密钥、连接串、主机、端口或内部服务地址。

### 2.6 契约、SDK 与错误边界

新增公共接口：

```text
GET    /api/v1/system/status
GET    /api/v1/workbench/tasks
GET    /api/v1/users/{userId}/preferences
POST   /api/v1/users/{userId}/preferences
PUT    /api/v1/users/{userId}/preferences/{preferenceId}
DELETE /api/v1/users/{userId}/preferences/{preferenceId}
POST   /api/v1/users/{userId}/preferences/{preferenceId}/reject
GET    /api/v1/feedback
POST   /api/v1/feedback
POST   /api/v1/tasks/{taskId}/cancel
GET    /api/v1/developer/traces/{traceId}
```

新增内部接口：

```text
DELETE /internal/v1/memory/{preferenceId}
```

- `packages/api-contract/openapi.yaml` 与冻结契约
  `contracts/openapi/tripagent-v1.yaml` 的 SHA-256 完全一致。
- generated SDK 新增 `DeveloperApi`、`FeedbackApi`、`PreferencesApi`、
  `SystemApi` 和 `WorkbenchApi`。
- generated runtime 的非成功响应统一转换为 `ApiClientError`，422 结构化
  字段详情可准确映射到表单。
- 401、403、404、409、422、429 和 5xx 继续转换为用户语义，不直接显示
  状态码、内部枚举或服务端原始异常。

## 3. 全链路浏览器验收

Playwright 的北京三日游流程覆盖：

1. 创建北京三日游并完成八步需求向导。
2. 上传脱敏 PDF fixture。
3. 等待后端 OCR 任务进入待确认状态。
4. 修正低置信字段。
5. 发起规划并等待后端任务完成。
6. 获取均衡和少通勤两个候选方案。
7. 并排比较方案差异。
8. 查看后端坐标驱动的地图路线和每日时间线。
9. 展开推荐证据。
10. 查看确定性冲突和修复建议。
11. 发起不覆盖旧版本的重规划。
12. 验证版本冲突后的恢复与重试。
13. 比较新旧版本。
14. 确认候选方案，不触发自动支付。
15. 提交反馈并验证偏好建议结果。

阶段十四辅助页流程同时覆盖：

- 工作台筛选、继续任务和取消任务。
- 拒绝模型推断偏好。
- 创建用户主动偏好。
- 提交地点反馈。
- 查看系统状态。
- 查询开发者追踪并验证敏感属性不可见。

## 4. 异常测试矩阵

| 场景 | 验证结果 |
| ---- | -------- |
| SSE 断开 | 自动由轮询读取同一后端任务事实源 |
| 后端 422 | 错误定位到具体字段，不展示协议或原始异常 |
| 重复提交 | 双击保护生效，只产生一次有效请求 |
| 幂等重试 | 重试复用同一个 `Idempotency-Key` |
| Agent 超时 | 显示任务未完成和可恢复操作 |
| 模型限流 | 显示稍后重试提示 |
| 检索无结果 | 明确说明当前依据不足 |
| 地图不可用 | 显示地图降级状态，时间线仍可使用 |
| 页面刷新 | 恢复当前旅行、任务和方案 |
| 任务取消 | 后端返回取消终态，工作台同步更新 |

每个浏览器主流程均收集未处理的控制台错误。已被业务界面明确处理的预期
冲突不计为阻塞错误，最终断言未发现阻塞性控制台错误。

## 9. 演示步骤

1. 按第 6.1 节启动演示模式并打开 <http://localhost:5173>。
2. 选择“开始规划”，创建北京三日游。
3. 依次填写日期、人数、预算、兴趣、节奏、必去地点和特殊需求。
4. 上传 `apps/web/e2e/fixtures/beijing-hotel-confirmation.pdf`。
5. 等待资料识别，修正高亮的低置信字段。
6. 发起规划并在进度页等待后端完成。
7. 在结果页比较两个候选方案，查看地图、时间线、预算、冲突和推荐依据。
8. 从冲突建议进入重规划，生成新版本并比较版本差异。
9. 确认候选方案后进入反馈中心提交方案或地点反馈。
10. 在偏好与记忆页查看推断结果，并演示修改、拒绝或删除。
11. 在行程工作台按目的地和状态筛选，继续或取消未完成任务。
12. 在系统状态页查看当前能力；开发工具启用后可演示脱敏追踪。

## 10. 已知限制

- 当前 macOS 执行沙箱不允许写入 `~/.colima`，本机 Docker daemon 未运行。
  因此 `docker compose config --quiet` 已通过，但“从空环境构建并启动完整
  系统”仍须在具备 Docker daemon 的发布机执行，当前不能标记为通过。
- Lighthouse 的隔离 Chromium 无法创建 WebGL 上下文，报告记录了一条
  MapLibre 环境诊断；正常 Playwright 浏览器流程中的地图和降级状态均已
  通过，且没有未处理的阻塞错误。
- MapLibre 和主入口 Chunk 仍有超过 500 KiB 的构建警告，不影响正确性；
  后续可继续拆分地图 Worker 和共享依赖。
- 默认 OpenStreetMap 瓦片仅用于开发和低流量验收。生产环境必须配置合规
  瓦片源，浏览器仍只能访问后端代理。
- 演示模式只验证契约、状态机和确定性流程，不代表真实模型、天气、检索或
  供应商质量。
- 当前确认操作只保存候选方案或费用动作授权，不下单、不支付。
- 开发者追踪依赖 Jaeger 中已有对应链路，并要求开发开关或可信管理员角色。
