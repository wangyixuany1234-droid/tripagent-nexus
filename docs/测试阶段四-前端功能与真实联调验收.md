## 2. 测试范围

### 2.1 组件与页面行为

- 旅行需求 Stepper、日期、预算、人数与服务器字段错误定位。
- 文件选择、上传、进度、重复文件和异常文件状态。
- OCR 低置信字段、人工修正和修正原因。
- Agent Progress、SSE 更新、断流后轮询和 Partial Success。
- 双方案比较、预算和通勤指标。
- 地图与时间线选择联动、地图失败降级和重试。
- 预算图表、冲突中心、证据抽屉。
- 锁定项、删除项、重规划表单和版本保留。
- Human-in-the-loop 行程确认与费用授权确认。
- Error、Empty、Loading、Partial Success 状态。
- 通知重试去重，避免同一错误重复展示。

### 2.2 Playwright 主流程

路由隔离 E2E 已覆盖：

1. 创建北京三日游并填写日期、人数、预算和偏好。
2. 上传脱敏订单 fixture。
3. 等待 OCR 并修正低置信字段。
4. 发起规划并通过 SSE 查看任务状态。
5. 获取、比较两个候选方案。
6. 查看地图、时间线、预算、证据和规则冲突。
7. 锁定行程项，重规划并比较版本。
8. 确认最终方案和费用操作。
9. 提交反馈。
10. 刷新后恢复草稿、任务和方案状态。

### 2.3 异常流程

- 422 错误映射到表单字段。
- 401 跳转登录并保留返回路径。
- 403 展示用户态权限提示。
- 409 展示版本冲突并保持幂等键。
- 429 展示 `Retry-After` 秒数。
- 500 仅展示问题编号，不泄露后端原始错误。
- SSE 中断后自动切换轮询。
- 地图不可用时每日时间线仍可操作。
- 证据不足时不生成来源链接。
- 刷新页面不重复提交规划任务。
- 连续点击不重复创建旅行。
- 请求失败后离开 Loading 状态并展示可重试状态。

## 5. 失败案例与修复

1. Node 实验性 `localStorage` 导致 37 项组件测试统一失败。
   修复为测试环境内的确定性内存 Storage。
2. JSDOM 缺少 `URL.createObjectURL` 和 `URL.revokeObjectURL`。
   增加文件预览 API mock。
3. 403 和 500 在 React Query 重试后产生重复通知。
   在通知状态层按标题和内容去重，并增加单元测试。
4. 旧断言与当前 accessible name、状态文案和货币格式不一致。
   改为基于 role、作用域和实际用户文案定位。
5. 地图重试涉及动态 import，原断言过早。
   改为等待 Map 实例重建条件。
6. 防重复提交测试曾通过固定延时保留请求。
   已改为测试控制的 pending route，不再使用固定 sleep。
7. 全量 Playwright 聚合运行写出 22 项成功结果后，工具沙箱在报告收尾阶段拒绝访问 `/` 并返回 1。
   主流程/异常和可访问性已拆分复跑，均以退出码 0 通过。
