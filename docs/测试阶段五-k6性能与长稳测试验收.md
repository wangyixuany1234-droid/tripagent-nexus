# 测试阶段五：k6 性能与长稳测试验收

## 1. 验收结论

本阶段结论为 **部分验收**。

- 幂等并发测试通过：20 次同键并发只得到一个业务资源。
- 同资源竞态测试通过：1 次写入成功，19 次明确返回版本冲突，无静默覆盖。
- 低置信 OCR 场景已修复：缺失日期的待确认订单可进入规划，计划最终为
  `PARTIAL_SUCCESS`。
- 修复后的 2 VU、5 分钟 Smoke 已实际执行，85/85 功能检查通过，HTTP
  错误率为 0，重复业务资源数为 0。
- Smoke 总体仍为 **FAILED**。QEMU TCG 环境下同步、写入、异步提交和异步
  完成延迟均超过原始门槛；门槛未放宽。
- Smoke 结束后数据库中的 10 个异步任务均已进入终态，无

  `task_permanent_stuck` 实际表示超过 35 秒轮询窗口，不能作为永久卡死证据。
- 资源采集器的串行 Docker 命令开销已修复。默认配置聚焦复测取得 6 个完整

- Load、Stress、Spike、Soak 和 SSE 未在 TCG 环境执行，不能给出正式容量

## 2. 测试环境与边界

本次真实系统测试运行在本地隔离 QA Compose，共 10 个服务。模型、OCR、MCP
及外部工具均使用 Mock 或本地 Stub，未访问或压测第三方服务。

由于宿主机硬件虚拟化不可用，Docker 运行在 4 vCPU、8 GiB 的 QEMU TCG
虚拟机中。Spring Boot 冷启动曾耗时 772.269 秒，且测试期间容器 CPU 可超过
单核 100%。因此 TCG 下的延迟只能用于诊断功能链路，不能作为生产容量基线。

安全边界保持不变：

- 高负载场景要求 `QA_HIGH_LOAD_APPROVED=true`；
- 外部工具 Mock 要求 `QA_MOCK_EXTERNAL_TOOLS_CONFIRMED=true`；
- 真实模型要求 `REAL_MODEL_TEST_ENABLED=true` 和独立 Canary 授权；
- 所有测试数据均为合成数据，报告不保存请求正文、授权头或 OCR 原文。

## 3. 修复内容

### 3.1 应用与契约

1. 增加 Prometheus Registry，恢复 `/actuator/prometheus`。
2. 使用 PostgreSQL advisory lock 修复同键幂等请求耗尽 Hikari 连接池。
3. A2A `WORKING` 任务改为轮询，并在超时或中断时请求 SDK 取消。
4. FastAPI decimal string 通过严格传输 DTO 显式转换为 `BigDecimal`。
5. JDK multipart 客户端固定使用 HTTP/1.1。
6. 低置信 OCR 的日期、金额、币种被声明为可选字段；JSON Schema 只移除
   明确标注为可选的字段，非空值校验仍保留。
7. Agent JSON Schema 增加线程安全缓存，避免每次请求重复编译。

### 3.2 k6 业务流

1. `WAITING_CONFIRMATION` 作为正常的人工审核交接终态。
2. 文档去重允许复用既有 taskId 和 resourceId，不再误报重复资源。
3. 无计划时反馈目标改用合法的合成 `PLACE`。
4. 幂等键同时保留 runId 前缀和后缀，避免长 runId 截断碰撞。
5. 非预期响应只记录 operation、status 和脱敏 traceId。
6. k6 Docker 容器使用调用者 UID/GID 写入报告，修复 Linux bind mount
   权限失败。

### 3.3 资源采集器

原采集器每个样本串行执行 9 个探针，并为多个指标重复启动
`docker compose`。在 TCG 下，一个 5 秒采样周期实际需要约 50 至 60 秒，
造成 20 次随机超时。

现已：

- 按 Compose project 一次解析并缓存容器 ID；
- 使用直接 `docker exec` 代替重复 `docker compose exec`；
- 并发执行互相独立的只读探针；
- 按固定采样周期扣除探针执行时间；
- 只记录 collector 名称和异常类型，不记录命令、凭据或响应内容；
- 提供采样间隔、并发数、HTTP 超时和 Docker 命令超时配置。
