# 测试阶段十一：前端稳定性与可访问性验收

## 结论

阶段十一已完成 Mock 路由隔离下的前端稳定性、响应式和可访问性验证。Chromium
与 WebKit 的可执行矩阵通过，Firefox 在当前 macOS / TRAE 沙箱中无法启动
Playwright 缓存浏览器，未进入应用页面，因此完整门禁状态为
`BLOCKED_ENVIRONMENT`，不能标记为通过。

本报告不包含真实后端小流量联调；真实小流量验收必须单独执行并单独出具报告。

## 修复与调整

1. 阶段十一稳定性采样原本离开结果页后跳回首页；首页本身包含示例地图，导致
   “残留地图 DOM” 被误判为泄漏。用例已改为跳转到不含地图实例的系统状态页，
   只验证结果页地图、图表和抽屉是否正确卸载。
2. `run_stage11_frontend.sh` 将 Playwright 的 `HOME` 和 `TMPDIR` 定向到仓库
   `.runtime` 目录，并保留原始浏览器缓存路径，避免 WebKit 收尾阶段访问
   `~/Library/WebKit/org.webkit.Playwright` 被沙箱拦截。
3. `stage11-summary.json` 统计逻辑已改为读取 Playwright JSON 的 `status` 和
   `results[].status`，不再使用不存在的 `outcome` 字段。
4. Firefox 启动失败会被识别为环境阻塞，summary 标记为
   `BLOCKED_ENVIRONMENT`，仍保持非通过状态。

## 失败样本

Firefox 失败发生在应用页面加载前。直接执行 Playwright 缓存的 Firefox Nightly
二进制并传入已存在 profile 目录，同样返回：

```text
*** You are running in headless mode.
Could not find profile folder.
```

完整矩阵结束后，TRAE 沙箱同时报告拦截：

```text
Not allow operate files: <home>/Library/Application Support/Firefox
```

因此当前失败不归因于前端业务代码、路由 Mock 或应用状态逻辑。
