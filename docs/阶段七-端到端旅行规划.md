# 阶段七：端到端旅行规划

## 完成项

- 从 `TravelRequirement` 和人工确认订单驱动八 Agent 规划。
- 后端检索公共知识和 Owner 范围内的用户记忆，身份不进入 Agent 消息。
- 输出 `BALANCED` 与 `LOW_TRANSIT` 两个候选。
- Java `PlanRuleEngine` 执行十三类时间、路线、预算、订单和证据规则。
- 自动局部修复最多一次，并保存为不可变后继版本。
- 保存方案家族、版本链、变更原因、用户指令、差异摘要和任务结果 ID。
- 复用统一任务状态、轮询和 SSE。

## 确定性规则

规则覆盖时间重叠、景点营业时间、通勤余量、每日密度、酒店入住、到达前
活动、离开后活动、总预算、分类预算、未换算币种、关键订单缺失、推荐无
证据和明显路线折返。

## E2E 覆盖

北京三日游验收验证：

- 创建旅行并保存需求。
- 上传脱敏航班订单，进入人工确认并修正缺失时间。
- 获取两个不同策略方案。
- 持久化 `COMMUTE_TIME_INSUFFICIENT` 冲突并生成修复版本。
- 保存总预算、每日预算和证据。
- 锁定交通、移除餐饮、调整预算/节奏并重规划。
- 旧版本不变，版本比较返回移除项和预算差。
- SSE 终态与轮询任务一致。
- 确认方案并提交反馈。

## 限制

- 生产规划通过 Outbox 和 Kafka；关闭异步治理时才使用本地虚拟线程调度。
- 未配置的真实天气、路线、汇率和营业时间工具失败关闭。
- Mock 证据与模型输出不可解释为实时数据。

## 验收

主流程 E2E、规则引擎、不可变版本、两方案、重规划、确认和反馈均由
自动化测试覆盖。
