# 阶段四：OCR 与多模态订单解析

## 完成项

- 先定义公共上传/修正 API 和 Spring 到 FastAPI 的私有解析 API。
- 支持 PNG、JPEG、WEBP、PDF，并校验大小、扩展名、实际 MIME、可执行
  文件签名、图片像素、PDF 页数和结构。
- 原文件进入 Owner-only 存储，数据库保存不透明键和 SHA-256。
- 通过 `(trip_id, sha256)` 和幂等键抑制重复上传。
- PostgreSQL Outbox 和 Kafka 驱动异步解析，任务支持轮询、SSE 和
  `Last-Event-ID`。
- FastAPI 先执行 OCR，再执行多模态语义抽取；生产使用
  Tesseract/Poppler 与 DeepSeek，测试显式使用 Mock。
- 结构化结果包含订单字段、置信度、文本证据和归一化区域。
- Java 校验倒置时间、越界日期、重复订单、金额/币种缺失、低置信关键
  字段和互斥交通时间。
- 人工修正保留原值、新值、Actor、原因和 UTC 审计时间。

## 启动

Mock：

```bash
DOCUMENT_PARSER_MODE=mock docker compose up --build -d
```

真实 DeepSeek：

```bash
export DEEPSEEK_API_KEY
DOCUMENT_PARSER_MODE=deepseek docker compose up --build -d
```

`DEEPSEEK_API_KEY` 只能由服务端环境或密钥管理系统注入。

## 测试

```bash
mvn -B -ntp -pl apps/trip-agent-api \
  -Dtest=DocumentParsingIntegrationTest test
services/ai-retrieval-service/.venv/bin/pytest -q \
  services/ai-retrieval-service/tests/test_document_parser.py
```

脱敏夹具覆盖酒店、航班、门票、缺失日期和重复订单。

## 接口示例

```bash
curl -X POST http://localhost:8080/api/v1/documents/parse \
  -H 'Idempotency-Key: upload-example-000001' \
  -F 'tripId=<trip-id>' \
  -F 'file=@services/ai-retrieval-service/tests/fixtures/documents/hotel-confirmation.png;type=image/png'

curl -N http://localhost:8080/api/v1/tasks/<task-id>/events

curl -X PATCH \
  http://localhost:8080/api/v1/documents/<document-id>/bookings/<booking-id> \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: correction-example-0001' \
  -H 'X-Actor-Id: user-123' \
  -d '{"corrections":[{"field":"startTime","value":"2026-10-01T07:00:00Z"}],"reason":"已核对脱敏确认单"}'
```

## 限制

- 未注入服务端密钥时不执行真实 DeepSeek 推理。
- 公共用户身份由上游网关提供；私有 FastAPI 使用服务 Bearer 鉴权。
- Mock 结果明确标记，不能作为真实供应商成功证据。
